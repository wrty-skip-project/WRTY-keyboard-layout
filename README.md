# WRTY-keyboard-Layout (Codename: SKIP / SK-Layout)
> **A QWERTY-remembered, single-screen ergonomics keyboard layout for mobile devices. Highly optimized for thumb-typing, featuring central vowel-cross aggregation and prior-art defensive publication.**

---

> **「最初は『WRTY』というロジックの骨格から始まった。けれど、完成したキーボードの上で指を動かしたとき、私の親指は軽快にスキップ（S-K-I-P）していた。だから、コードネームは『すきっぷ配列（SK）』。」**
> 
> **「開発の辿り着いた先に、鉛筆でなぞる感触と、止め跳ね払いのリズム感を再発見した。」**
> 
> PCのタイピングは爆速なのに、スマホの50音フリックには脳が馴染まない。かといって、スマホ画面でのQWERTY入力はキーが小さすぎて誤爆だらけ。
> 
> 本配列は、そんな背景を持つ一人の「スマホQWERTY難民」が、親指を自由に「スキップ」させ、その開発の辿り着いた先に、鉛筆で文字をなぞる感覚と止め跳ね払いのリズム感を再発見した、一画面完結型のモバイル・ローマ字入力システムです。

## 🧭 開発コンセプト：QWERTYへの未練と、長文での疲労軽減

本配列の根底にあるのは、QWERTY配列という慣れ親しんだ過去への「断ち切れない未練」です。しかし、それをそのままスマホに持ち込んでも画面の狭さによる破綻でした。
そこで、PCネイティブとしての「空間記憶」を肯定しながら、スマートフォンが持つ「身体性」を融合させ、長文を打つ際の親指の負担軽減と、アナログな筆記の快感へと昇華させるアプローチをとりました。

*   **親指の可動域を半径1.5cm圏内に固定**：文字盤の端から端へ指を大きく往復させる必要がなくなるため、長文入力時の手の疲労感が軽減されます。
*   **「記号・数字のモード切り替え」を排除**：記号画面やテンキー画面を連打して往復するロスを排除。入力中の画面のチラつき（視覚的ノイズ）をなくし、フリック時の認知疲労を抑えます。

## 📊 3つの配列における移動量・負荷の比較（AI推定）

日本語・英語・数字・記号が高度に混在する解説文を入力した際の本配列の優位性を、AI（LLM）を用いたタイピング運指シミュレーションによって判定したデータです。

### 📋 シミュレーション対象文章の構成要素・文字数内訳
効果判定の根拠を明確にするため、計測対象となったテスト文章（「モード切り替え地獄」の解説文）の文字種類ごとの厳密な文字数を以下に開示します。

*   **対象文章**：`1. 通常のかなフリックの「モード切り替え地獄」を完全回避通常のかなフリックは、大和言葉には強いですが、今回のように「QWERTY」「69%」「()」が頻出すると、その都度「英数画面への切り替え」「記号画面への切り替え」「かな画面への復帰」という無駄な移動とタップが大量に発生します。SK配列は、右フリックに数字(1〜9、0)、特定フリックに記号(%やカッコなど)が多層化されているため、画面を1回も切り替えることなく、すべて1画面のシームレスな運指で完結します。その結果、かなフリックよりも総アクション数自体が少なくなっています。`
*   **総文字数**：**251文字**（スペースを除く）
*   **文字種類別の内訳**：
    *   **ひらがな・カタカナ・漢字（和文）**：**214文字**（構成比：85.2%）
    *   **英文字（アルファベット大文字・小文字）**：**14文字**（構成比：5.6%） ※`QWERTY`, `SK`
    *   **数字（半角・全角）**：**6文字**（構成比：2.4%） ※`1`, `69`, `0`
    *   **記号・各種カッコ・句読点**：**17文字**（構成比：6.8%） ※`「」`, `()`, `%`, `、`, `。`

### 🔍 効果判定の根拠と計測方法
*   **計測アプローチ**：一般的なスマートフォンの画面幅（約70mm、キーピッチ約15〜20mm、フリック1動作5mm）を基準とし、上記の混在文を入力した際の指先のX・Y座標の移動ストロークおよび「モード切り替えに伴う画面四隅への往復動作」をAIにより数理的にエミュレート・合算しました。
*   **判定の限界**：本数値は実際の指の動きをセンサー等で測定した実測値ではなく、運指パターンから導き出したAI丸投げシミュレーションによる推定値です。QWERTY配列の広範囲な往復や、かなフリックの「18回のモード切り替え」による移動ロスに対し、本配列の「ホームポジション集約」と「`•`ハック（予測変換へのダイレクト集約）」がもたらす中央狭範囲への閉じ込め効果を数理的に証明したものとなります。
*   **英和の往復について**：英長文を入力する際の（かな⇄ABC）の往復（本シミュレーション内では2回と仮定）は発生しますが、左一等地に配された独立ダイレクトキーによる最小限の移動で処理されます。

## 🛠️ 『WRTY配列』を構成する 6つの方針

### 1️⃣ 子音配列に詰め込んだ「QWERTYへの未練」と空間記憶
アルファベットの配置は、ユーザーが長年PCで培ってきたQWERTY配列の空間認知をそのまま引き継いでいます。本配列の「名称（看板）」の由来そのものです。
*   **左側ライン**：`W`、`S`、`C` などの左手担当キーを配置。
*   **右側エリア**：`Y`、`P`、`K`、`M` などの右手担当キーを配置。
*   **高さの段位**：最上段に **`W・R・T・Y`**（QWERTYからモバイルに不要な文字を引いたもの）、中段に `S・K`、下段に `C・N・M` を残すことで、「あの文字はあの辺りにある」という指の記憶をそのままスマホに移行させ、学習コストを軽減しています。

### 2️⃣ 母音の十字集約 ＝ 「あ行フリック」を流用
中央の特大ホームポジションキー（幅2.1マス）に `A` を配し、左に `I`、上に `U`、右に `E`、下に `O` を十字フリックで割り当てています。
ここに、日本人が無意識に指に染み込ませている「通常のかなフリックの『あ・い・う・え・お』の方向」を融合させました。QWERTYの記憶で子音を叩いた後、母音の処理だけはスマホの記憶をそのまま活かして**スライド入力。**

### 3️⃣ 連母音（ou / ei）に宿る「止め跳ね払い」のリズム
**漢語由来の日本語（音読み）**の構造上、最頻出する2つの連母音（子音＋ou / 子音＋ei）において、指先がリズミカルな往復運動をするのは、幸運な偶然（セレンディピティ）です。
*   **「〜おう（ou）」**：中央キーの垂直線上（下➡️上）の一直線なピストン運動へ変化。下にグッと引いて止めた勢いのまま、上へと鮮やかに「跳ね上げる」運指になります。
*   **「〜えい（ei）」**：水平線上（右➡️左）の滑らかなワイパー運動へ変化。親指の付け根を軸とした自然な扇形の旋回運動にシンクロし、美しい「はらい（払い）」の軌跡を描きます。
指に急ブレーキをかけることなく、運動エネルギーをそのまま反転させて**「2ストローク」**で処理できるため、タイピングが心地よい鉛筆のステップへと変わります。

### 4️⃣ 促音（っ）連打のための「P」独立配置
「漢語由来の日本語」や「カタカナ外来語」の音声構造を分析した**妥協**です。
*   外来語で頻出する「〜ップ（アップ、コップ、タップ等）」の促音便において、同じキーの2回フリックは指にとって負担です。
*   あえて統計データを無視し、`P` を独立1キー（タップで発動）として常駐させることで、PCと同じ「親指でポンポンと2回タップ（連打）するだけで『っ』が仕込める」肉体的快感を獲得しました。空間配置もQWERTYの「右手小指の記憶」を継承しています。

### 5️⃣ 言語学に基づく「硬口蓋音の立体収納」と『隔離配置』
日本語において極めて必要度の低い `C`, `X`, `Q` の3文字は、一等地から移動して、最下段左端の1キーへ**「隔離配置」しました。**
*   しかし単に除けただけでなく、音声学においてこの3文字は「同じ舌のフォームで作られる音（硬口蓋音）」のグループであるという裏付けを利用し、`C` の上下フリックに `X` 和 `Q` を格納。音韻論的スッキリ収納を実現しています。
*   ※同様の類似音連携として、`Y`（や行）の下フリックに `J`（じゃ行）を隠すペアリングも徹底されています。

### 6️⃣ 記号モードを終わらせる「`R`上フリック（`•`）× 予測変換」ハック
キーボード内に無数の特殊記号を詰め込むのをやめ、`R` の上フリックに万能のトリガーキー「`•`（中黒）」を1つだけ配置しました。
*   **「`•` を出す ➡️ 予測変換バーに並んだユーザ辞書の記号を直接タップする」**
*   [iOSの「azooKey」](https://azookey.com)や[Androidの「スミレ」](https://github.com)の予測変換機能を活用した、変換操作すら挟まない超高速の2ステップ入力です。キーボードの画面を1ミリも切り替えることなく、登録したあらゆる特殊記号（％やカッコなど）を瞬時に呼び出すことができます。
